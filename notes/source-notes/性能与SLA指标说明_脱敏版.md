# 性能与 SLA · 指标说明

版本 PERF-01，更新于 2026-11-08。本文定义 Demo 的统计口径，不代表行业标准或生产监控已接入。

## 三类数据不能混算

1. **请求遥测**：固定生成的 1,248 条请求样本，覆盖 2026-11-01—11-07；截至 2026-11-07 23:59:59（UTC+8）。模型、版本和耗时均为模拟，不从旧首响数值反推 TTFT。
2. **客服会话**：固定模拟问题样本，按日期、渠道计算首响和服务结果，不被请求级助手、模型筛选影响。历史服务概览的首响样本仍按 OP-01 定义保留，不与本批样本合并。
3. **本地调度**：项目助手在浏览器实际执行的步骤只在“助手协同”统计，不混成生产模型速度。

日期是固定历史样本，不是“今天”的实时业务。请求样本量不是独立客户数；模型请求与会话不能用相同分母。

## 延迟定义

| 指标 | 起止事件 | 样本边界 |
|---|---|---|
| 首 token 延迟 TTFT | 模型请求发出 → 首个内容 token | 已观测首 token 的调用；不计占位事件或仅含角色的流式块 |
| 完整生成 | 模型请求发出 → 最后一个内容 token | 已完成模型生成的调用；含 TTFT |
| 端到端处理 | 平台受理任务 → 结果交付确认 | 仅成功请求；接待为渠道确认，填单 / 质检为内部结果交付 |
| 调度排队 | 平台受理 → 助手执行开始 | 已出队请求；仍排队的等待时长只在请求详情列下限 |
| 工具调用 | 工具请求发出 → 返回 / 超时 | 每次尝试分别计数；包括超时、失败，重试不合并 |
| 渠道入站 | 渠道事件产生 → 平台收到事件 | 不包含在端到端内；生产需做时钟校准、幂等和事件去重 |
| 交付确认 | 平台提交结果 → 渠道或调用方确认 | 成功交付的阶段；确认接收不代表客户已阅读 |
| 内容块最大间隔 | 单次模型调用中相邻内容块的最大间隔 | 先按调用求最大间隔，再跨调用取分位；不是单 token 的 TPOT |

P50 / P95 / P99 使用 nearest-rank：按当前范围逐条有效值排序，取 `ceil(n × p)` 对应位置。不得平均各天 P95 或把各环节 P95 相加。每项保留自身 n；无样本为“—”，不是 0 ms；n < 100 的尾部分位注明仅供观察。

成功请求的阶段按时间顺序组成一个非重叠时间线，完整生成是“等待首 token + 剩余内容生成”的派生统计，不再叠加一次。阶段最长是排查线索，不自动判定根因。失败后未执行的阶段不补造。

## 成功与目标达标

- 有效终态请求 = 成功 + 超时 + 失败。
- 请求成功率 = 成功 / 有效终态。
- 请求超时率 = 超时 / 有效终态；请求失败率同理。
- 端到端目标达标率 = 在目标时间内成功交付 / 有效终态。超时、失败均算未达标。
- 取消和处理中单列，不纳入有效终态，也不会默默删除。实际实现应另行定义用户取消、系统取消和超时竞态的规则。
- 工具失败尝试包括超时和错误；分母为所有已结束尝试。发生重试的请求数与尝试数分开。

初始演示目标：TTFT P95 ≤ 1.5 秒，端到端时限 10 秒、达标比例 95%，AI 客户首响 15 秒、人工首响 60 秒。用户可调整，值仅在本地保存，并重算同一份固定样本。它们不是合同 SLA、行业基准或告警配置。

## 客服项目指标

| 指标 | 分子 / 耗时 | 分母与注意事项 |
|---|---|---|
| 客户首响 SLA | 在接待方式对应目标内提供首条实质回复 | 已过首响目标的有效问题，未回复仍计未达标。按自然时间，不含营业日历配置 |
| AI / 人工首响 P95 | 客户进线 → 首条实质回复获渠道确认 | 按首次接待方式分别计算，排除“已收到”占位回复；不能用 TTFT 替代 |
| 人工排队 P95 | 进入人工队列 → 坐席接单 | 已接单的人工队列记录，不是助手任务队列 |
| AHT | 人工忙时 + 后处理时间 | 已结束的人工处理记录；排除排队及客户等待，不把在线时长当忙时 |
| 解决时长 P95 | 进线 → 确认解决 | 有解决证据的已解决问题，未解决件数单列；关闭会话不等于解决 |
| 转人工率 | AI 起始后曾转人工的问题 | AI 起始问题；直接进入人工队列不放进分母 |
| FCR（24h） | 第一次联系有解决证据且 24h 内无同问题再次联系 | 进线后已完整观察 24h 的问题；样本中第一次联系结束的判断为预置事实 |
| 重复咨询（24h） | 进线后 24h 内同一问题再次联系 | 已完整观察 24h 的问题；不把重复投递、跨渠道副本算新咨询 |
| 重开率 | 确认解决后 24h 内再次进入处理 | 解决后已完整观察 24h 的已解决问题，与进线观察窗不同 |
| CSAT | 5 分量表中 4–5 分评价 | 有效评分；附问卷响应率，不把未评分当满意 |
| 评价响应率 | 有效评价 | 已发出的评价邀请，不等于全部客户 |

单日 11 月 7 日样本尚未完成 24h 观察，FCR、重复咨询及重开显示“—”。没有观测数据时不补为零或百分之百。

## 下钻与回流

1. 日期、渠道、助手、模型筛选联动请求指标、分位数、图表及列表。
2. 点击趋势日期只进一步过滤请求列表；点击分布区间会切换到全部状态再筛选时长，页面保留下钻范围与清除入口。
3. 查看请求事件、模型标签、助手版本、阶段状态及工具重试。客户端取消、超时和处理中有不同文案。
4. 确认后手动导入所属助手的执行追踪。来源始终为“预置性能样本（模拟）”；相同样本重复导入复用 Trace，不绑定真实客户。
5. 在具体步骤登记问题，人工补齐原因、预期与修正方案。性能样本没有自动评测适配器，不能因此生成“性能回归通过”或自动发布。
6. CSV 导出含目标、范围、分位数、各自样本量、终态计数、会话指标及请求明细；不含客户原文、模型密钥或媒体。

## 正式接入仍需建设

应在渠道连接器、调度器、模型网关、工具服务和消息发送层记录关联事件，保留租户 / 项目、请求 / 会话、助手版本、模型配置、阶段、开始与结束时间、状态、错误码、尝试号与取消原因。禁止将客户原文、密钥或鉴权头作为指标标签；客户标识和执行 ID 不进入高基数指标维度。

生产侧需要时钟校准、事件去重、延迟到达处理、直方图聚合、超时与取消仲裁、保留期和访问控制。建立营业时段 SLA、排班及并发采集后，才能计算坐席占用率；建立模型流事件和账单核对后，才能计算 TPOT、Token 成本与单位解决成本。

真实 TPS / 并发、TPOT、成本、坐席占用率和告警通知目前明确标记“未采集”。本次未连接真实模型或客户渠道，没有验证生产容量与监控准确性。
