# 连山 · 项目协作与 Orbit 助手研发

先在项目集中选择项目，再进入该项目自己的项目助手、协作群和业务助手。外层没有侧栏或孤立文件夹图标；内层通过文字“返回项目集”和项目名称切换。连山品牌、原台账、对话和助手版本保持不变。

每个项目有独立的项目助手配置与团队。Orbit 承接本项目的业务场景研发、案例验收、纳入团队和问题回归；原售后图谱、接待、填单与评分保留。全为本地交互演示，不代表已连接 Orbit 原应用接口或生产业务系统。

## 打开

- 运行本目录的 `node server.js`，入口 `http://127.0.0.1:4333/?v=project-orbit#portfolios`。先筛选项目集并选择具体项目；旧 `#portfolio` 也回到选择页。
- 进入项目后地址带 `project` 参数，例如 `/?project=AFTERSALES#manager` 和 `/?project=RETAIL#group`。无有效项目的旧助手深链先回选择页，避免默认打开售后团队。
- 业务助手 `/?project=AFTERSALES#agents`，大盘问数 `/?project=AFTERSALES#dashboard`，性能 `/?project=AFTERSALES&view=performance#analytics`。
- 便携演示：同级的 `连山_项目助手与Orbit研发_交互Demo_脱敏版.html`，无需安装。不启用真实模型测试或语音识别。原连山和汇声各版本 HTML 均保留。
- 项目内沿用 `#group`、`#graph`、`#reception`、`#forms`、`#scoring`。新增 `#project-assistant`、`#orbit`、`#custom-assistant`，必须有所属项目。
- 售后浏览器存储键继续使用 `servicehub_demo_project_v13`；新增项目集台账使用 `servicehub_portfolios_v1`。不复制旧版客户消息、模型密钥或草稿。

## 按助手组织工作区

外层不显示助手导航。进入售后项目后保留项目助手、项目协作群、客服收件箱、业务助手；其他项目显示自己的项目助手、群、业务助手和项目任务，不出现售后的坐席与客户数据。

## 按项目配置助手，接入 Orbit 研发

- 项目助手可独立配置名称、目标、受理范围、人工升级条件、资料引用、Prompt 草稿和授权成员。每次保存记录配置版本，默认不共享其他项目配置。
- 项目群仅显示本项目成员。支持文字、@ 选择、键盘选择和单聊转群确认。未经授权或已暂停的成员不能接新分派；原售后群保留附件和听写，其余项目本轮为文字协作。
- 预置部门助手尚无执行适配器，只记录“待配置”任务，不伪造已处理。经 Orbit 本地验收的定制助手可实际执行关键词分流、字段检查、摘要或表单草稿整理，结果保留版本与处理步骤。
- 从项目助手或业务助手目录进入 Orbit，创建当前项目的场景；配置受理关键词、必要字段、补充转人工词、允许的本地动作及处理边界。知识和模型仅保存引用意图，不自动读取知识、不保存 API Key、不调用真实模型。
- 案例可人工编写或添加明确标为示例的三类样本。人工确认预期后才可通过；零案例、未审核案例、失败或过期验收不能纳入团队。
- 规则和案例改变后旧验收失效，历史结果保留。全部通过后还需填写原因并确认目标项目，才将助手纳入本地群与调度名单；同一验收不重复生成版本。
- 每位定制助手单独保留执行追踪、问题案例、回归样本与版本。问题需要人工给出预期、确认加入原场景回归；修正后重新验收，保留 V2，V1 及其原始执行记录不改写。历史配置可恢复为研发草稿，但不能跳过当前案例验收直接回退运行版本。
- 参考原 Orbit 的“场景 → 验收 → 留版”对象关系。本次未连接原 Orbit 的后端、数据库或 API，不迁移其私有对话；没有实现生产助手部署、跨项目鉴权或真实多用户群聊。

| 责任助手 | 管理的业务工作区 |
| --- | --- |
| 售后接待助手 | 智能接待为主，客服收件箱与知识维护为支撑 |
| 工单填写助手 | CRM / QMS 字段提取、来源核对、模拟提交回执；原工单记录保留 |
| 对话质检助手 | 完整会话评分、证据与标准版本；发送风险复核单独保留 |
| 大盘助手 | 问数与简报、运营大盘及性能与 SLA、业务图谱 |

工单、质检、知识、运营大盘不再单独占据主导航图标。原地址保留，进入后展示责任助手和工作区标签。渠道接入改从项目设置进入；查找功能支持按责任助手定位。

每个工作区同时提供职责配置、执行追踪、问题案例、回归样本、评测与版本。项目助手只协调与汇总，不接管各业务助手的台账和版本。原三位助手的配置与数据不重置，只追加大盘助手。

## 接待、填单与会话质检

- 接待助手先利用适用的已发布知识准备回复。试接待区记录继续自助 / 转人工建议；主动找人工、风险与未知问题保留人工出口。试接待占比不计为线上转人工率，未获得客户确认不得记为解决。
- 系统填单从客户消息提取型号、版本与描述，显示消息编号。CRM 与 QMS 使用不同字段模板；批次、责任组等缺失项不猜填。核对全部必填项并确认后才生成本地模拟回执；同系统 + 同会话阻止重复提交。原工单台账与外部系统模拟记录分开。
- 质检展示完整上下文，可分别评人工坐席、接待助手或全部服务方。无人工消息时不把 AI 消息冒充坐席。默认五维标准为事实依据30、规范25、需求完整20、表达15、交接闭环10分；只做简单风险规则预检，正式得分须人工逐项选择、提供证据和依据。
- 评分标准权重必须合计100，修改生成新版本；每次评分保存当时的对话与标准快照。评分的 Trace 属于质检助手，可继续登记案例；未接入自动语义评分、真实 CRM / QMS、自动回归或生产发布。

## 业务图谱

- 入口在大盘助手业务标签；也可从 Top 5 详情携带问题、日期、渠道进入。展示问题、型号、版本、领域、环节、来源案例、知识索引与原因假设，节点和连线均可选择查看依据。
- 支持搜索、待确认目录、日期 / 渠道 / 领域筛选、含佐证案例筛选、缩放、拖动画布与复位。右侧显示来源、反证、缺口及核验动作；零样本不生成关系图。
- 关联检索在固定样本上执行型号与版本约束、结构化遍历、实例去重，显示结果和路径并生成大盘助手的 Trace。路径是可审计处理摘要，不是模型隐式思维。仅预置知识索引没有正文，不冒充已发布知识。
- 新问题复用原有候选审核、规则检查与人工发布；当前本体更新后图谱标记已知定义，历史统计仍使用 v0.2，不自动重算历史。
- 设计参考 Microsoft GraphRAG 官方 Local Search 文档中“实体、关系、来源片段”的组织方式。本版没有运行其生产索引、向量召回、社区归纳或模型生成；不能把这个可视化 Demo 称为已完成的 GraphRAG 后端。参考来源：`https://microsoft.github.io/graphrag/query/local_search/`，2026-11-08 查阅官方仓库对应文档。

## 大盘助手

- 可以查询问题 Top 5、首 token P50/P95/P99、超时、慢请求、客服首响、CSAT、人工复核正确率和运营简报。输入框支持 Enter 提交、Shift + Enter 换行，也提供四类常用问法。
- 范围为固定的 2026 年 11 月 7 日或 11 月 1—7 日样本，可筛选渠道。当前日期、实时信息和其他未采集范围不会套用历史数据回答。
- 结果包含范围、样本量、分子分母、限制与来源入口。无样本显示缺失；未成熟观察窗不报 0% 或 100%。最长阶段仅作为单条排查线索，不冒充确认根因。
- 分析记录最多保留 40 条，刷新可回看；下钻恢复当时范围和请求。历史结果不随当前目标变动而改写。重置售后演示会清除这些记录，不删除其他部门台账。
- 在项目协作群可 `@大盘助手`，显示项目助手分工、大盘助手接单和分析结果。统计查询不使用关联客户会话，也不会虚构客户处理任务。附件解析和多个业务助手混合指令不支持时明确提示。
- 每次本地查询产生大盘助手自己的 Trace，可登记问题、填写人工归因并加入回归样本。问数自动回归适配器尚未接入，样本保留为待人工验证，不套用填单规则制造通过率，也不会自动发布。
- 这是固定样本上的规则化问数，不是开放式模型对话、真实经营成绩、实时告警或自动 GraphRAG 根因分析。只读查询不修改指标、退款、发客户消息或替代审批。

## 新增助手的模型连接

四位业务助手均有独立的模型连接入口。更新后的服务端支持独立保存和逐次授权测试；测试只使用固定连通性问候，不携带客户记录。大盘分析仍使用本地统计函数，不因连接测试通过而切换成真实模型分析。

如果页面已更新，但仍运行旧服务进程，新增大盘助手会显示“本机服务尚不支持这位新增助手”，禁用密钥输入，只允许保存配置草稿。确认后重启更新后的服务即可启用；重启会清空其他助手在进程内存中的密钥，需要重新输入。不会为了更新界面强制重启或迁移用户凭证。

## 项目空间：先整理项目，再进入工作

- 不再展示独立 PMO 面板、大数字汇总、部门总表和多层项目集页面。原项目集数据作为分组保留，分组只作为列表筛选条件。
- 外层不设置孤立的“项目”图标。内层用文字“返回项目集”回到所属范围，也可点项目名称切换，不清空任务和对话。
- 支持全部项目、收藏、归档三个范围；可搜索项目名称、说明、团队或负责人，按分组筛选，按最近更新、最近打开或名称排序。卡片 / 列表显示偏好会保存。
- 支持新建和编辑项目，移动分组，新建 / 重命名分组。新建表单优先填写名称、业务范围、分组和负责人；团队、阶段、里程碑和日期放入折叠区。
- 点项目直接打开该项目自己的项目助手。售后沿用原工作区；其他项目拥有独立单聊、群、团队、研发场景与任务台账。
- 项目菜单支持归档与恢复，均需确认。归档只是从常用列表移到已归档，不删除数据、不撤销权限、不停止运行中的任务；原链接仍可查看。
- 现有存储和项目 ID 不变，只追加收藏、归档、最近打开 / 更新时间等字段，不自动重命名或创建新的业务项目。数据由本机浏览器保存，并非多用户协同后端。
- 任务支持本项目内分派、状态、截止日期、卡点与完成说明。阻塞和完成必须填写依据；不会因此运行模型。
- 其他项目不会共享售后客户、模型连接、知识或执行记录。部门预置助手仍是职责草稿；通过本项目 Orbit 验收的定制助手才使用本地规则演练，不代表部署真实模型或接通渠道。
- 重置售后演示不删除其他项目台账。这不是生产级权限隔离、跨项目执行引擎或全功能项目管理系统。

## 性能与 SLA

- 新增独立标签，保留问题 Top 5、服务概览、质量回流和助手协同。
- 展示首 token、完整生成、端到端、调度排队、工具调用、渠道入站、交付确认、内容块最大间隔的 P50 / P95 / P99 和有效样本量。
- 请求成功、失败、超时、取消、处理中分别统计；有效终态分母为成功 + 失败 + 超时，超时和失败不会从达标率分母中消失。
- 延迟趋势柱状图、分布柱状图、慢请求列表联动；筛选日期、渠道、业务助手和模型，可修改演示目标并导出当前范围 CSV。
- 请求详情提供事件时间线、最长阶段线索与工具尝试，经过确认后可导入所属助手的 Trace、登记问题案例。去重导入，不自动训练、回归通过或发布。
- 客服会话独立展示首响 SLA、AI / 人工首响、人工排队、AHT、解决时长、转人工、FCR、重复咨询、重开、CSAT 及评价响应率。观察窗未成熟显示无样本。
- 全部性能数据来自固定模拟样本，目标不是行业标准。真实模型流式事件、成本、并发、坐席排班和告警未接入。详细口径见本目录《性能与SLA指标说明_脱敏版.md》。

知识标题占桌面表格约一半宽度，类别、知识编号和更新日期合并为次级信息；适用范围、状态、负责人和审核操作保留。标题自然换行，短屏滚动完整页面，手机改为分组列表；搜索空态有明确反馈。

## 原售后项目的多媒体输入框

- **附件**：选择图片、视频或音频；支持在输入框粘贴截图或拖入文件。支持格式列在文件选择器中，拒绝 SVG、空文件、伪装文件头或无法预览的编码。
- **本地预览**：图片直接预览，视频和音频使用播放控件。每条消息最多 6 个附件；单张图片 10 MB、音视频每个 50 MB，当前页面附件合计 120 MB。
- **敏感信息确认**：先预览并检查画面、声音、文件名与元数据，逐项确认后才可加入对话。这里只检查格式和可解码性，未实现图片 OCR、音频内容扫描或完整 DLP，用户勾选不等于系统已完成脱敏。
- **保留范围**：文件只保留在页面内存，不上传服务器、不发给模型，不把文件名或二进制写入浏览器持久存储。刷新后只留下附件占位提示；重新添加不会与旧附件混淆。请勿使用真实客户资料。
- **语音转文字**：本机服务页面中，在浏览器支持时先显示单次授权说明。用户确认后调用浏览器识别服务，可能传送音频给浏览器服务商。最多听写 60 秒，停止后先核对文字，再放入草稿；不会直接发送。权限拒绝、无语音或连接失败均有明确提示。不支持时保留文字输入与音频预览，不伪造转写。
- 附件加入对话后仅可预览，不能据此声称已分析画面、视频或音频。需要先补充文字说明，才能按现有本地规则安排任务。

## 项目助手与项目群

- 协调入口统一为“项目助手”，名称和职责按项目配置；“项目负责人”专指负责审批与决策的真人，沿用当前存储键、任务和助手版本。
- `@项目助手` 是新的提及名称；旧草稿中的 `@项目经理` 仍可识别。候选列表只显示新名称，历史消息、指令与执行快照不批量改写。
- 左侧独立「项目协作群」入口（`#group`）与「项目助手」单聊并列，支持刷新直达；草稿与附件分别保留，不再用顶部页签切换。
- 在群输入框输入 `@`，用鼠标或上下键选择项目助手、售后接待助手、工单填写助手、对话质检助手或大盘助手。Enter 选择，选完后再发送；Shift + Enter 换行。
- 单聊里提及其他助手时，发送前明确确认“转到项目群”，不会悄悄扩大消息可见范围。
- 群里展示项目助手的 @ 分工、助手的接单和完成消息；消息来自本地任务引擎的步骤事件，不是随意轮播的假进度。右侧可查看任务状态、暂停、继续或重试，关联 Trace 可回查。
- 只 @ 填单助手执行工单准备流程，只 @ 质检助手执行复核流程。公共的上下文整理、质检与结果汇总仍作为必要步骤保留，并不因 @ 而绕开检查。
- 没有足够历史数据时不伪造预计完成时间。群内任务仍为模拟，不派出真实专家、不发客户消息、不提交真实工单。

## 项目分组与助手版本

- 归属：工作空间 → 项目 → 项目助手与业务助手。项目可放入分组便于查找；原项目集名称保留为分组名称，不再新增一层操作入口。
- 原售后流程和各项目新建定制场景使用不同的本地执行器，保留原业务数据。未实现生产跨项目权限、跨项目调度或其他项目的真实数据接入；不把一个项目的数据伪装成企业全量数据。
- 业务助手目录不再放一套共享生命周期标签。进入具体助手后，分别查看配置、执行追踪、问题案例、回归样本、评测与发布。
- 项目助手自己的协调问题也单独保存。内部知识查找步骤归售后接待责任范围；原 Trace 仍保留执行方名称，不改写历史记录。
- 每个助手独立保存候选规则、版本、样本修订、评测快照、审核意见、发布和回退记录；发布某助手不会改变其他助手的评测基线。
