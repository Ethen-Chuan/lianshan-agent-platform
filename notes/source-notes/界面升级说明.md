# 运营工作台版 · 设计与指标说明

日期：2026 年 11 月 8 日。基于视觉识别版，不改变原有业务审批边界。

## 助手命名

业务角色统一为“售后接待助手”“工单填写助手”“对话质检助手”。上层为“项目助手”，负责协调任务；配置、试运行、调度状态、Trace 和大盘使用一致称呼。

执行步骤和按钮仍写动作，例如“填写工单草稿”“配置策略”，不混用角色名称。旧缓存仅更新显示名称，不重置运行策略；审计事件和执行记录的原始正文不改写。

## 三个运营视图

**服务概览**：上方看结果，中间看趋势和分布，下方比较渠道、问题类型并处理待办。四个指标共用一个紧凑区域，用数字、分子分母和变化建立层次，减少重复卡片。曲线有坐标、图例、键盘选择和明细，不做装饰性微型图。

**质量与回流**：人工抽检使用固定样本；问题修正读取现有 Trace 中的 Bad case、样本、评测和发布记录。两类范围分别标明，后者不是转化漏斗，不假设一一对应。

**Agent 协同**：读取项目助手本地任务和步骤，显示运行、排队、完成和失败。没有调用真实模型，不报告伪造的生产成功率、Token 费用或专家响应。任务详情复用原页面，不重复建任务。

## 固定样本口径

| 指标 / 范围 | 定义 |
| --- | --- |
| 日期 | 2026-11-01 至 11-07，结果截至 11 月 7 日 20:00 |
| 比较期 | 7 天对比 10 月 25–31 日；11 月 7 日单日对比 10 月 31 日 |
| 渠道 | 微信客服、钉钉、飞书模拟实时服务；不含存档 |
| 有效问题 | 每条记录代表一个已去重的服务诉求 |
| 确认解决 | AI 独立解决 + 人工协同解决，两类互斥 |
| AI 独立解决率 | AI 独立且有解决证据的问题 / 全部有效问题 |
| 未解决 | 已知未解决与结果待确认分开；未回复不视为解决 |
| 复核正确率 | 正确适用答案 / 已复核适用答案；每个抽检问题取一条答案 |
| 错误分类 | 每条错误仅计一个主要原因；总和等于错误样本数 |
| 首响 P50 / P95 | 按当前范围的首条实质回复时长样本计算，排除占位回复 |
| 变化 | 数量采用相对增幅，比率采用百分点；无基线则不算增幅 |
| 零样本 | 显示空态和“—”，不显示满分或非数字 |

样本由固定配置和固定种子排列构造，日期、渠道、分类、结果与复核统计来自同一记录集，可以守恒对账。95% Wilson 区间只是模拟样本统计，不代表实际客户业务。

## 可操作的部分

日期 / 渠道筛选联动指标、图表与导出；点击渠道行可下钻。趋势支持问题量 / 解决率切换，选择节点读取精确数值，“数据”展开明细。

指标口径可以就地展开，也保留单项说明。导出在确认窗口打开时固定范围，确认后下载模拟聚合 CSV，不含客户姓名、聊天和本地待办。

待办跳到待复核记录、待接管客户、待审核知识或问题案例，不自动代替人工操作。本地待办不受历史样本筛选影响，也不混算成历史业绩。

回流仍需人工归因、样本确认与评测审核；回归通过不等于业务正确，不自动训练。Agent 负载按页面打开或手动刷新时的本地状态展示。

## 视觉与适配

延续石墨导航、暖中性色与原创身份插画。大盘使用灰绿结果色和陶土对比色，状态有对应文字；提高数字、表格与标注层次。工单和质检指标区使用一致尺度。

桌面采用趋势 / 分布、分类 / 待办的双栏布局；手机依次堆叠，指标变成两列。宽表只在自身容器内横向滚动。窄屏增加曲线标注字号，保留数据明细与全部功能入口。

根地址仍是项目助手，全部是本地演示；没有新增真实模型、渠道、专家端点或业务 API。新存储键不覆盖旧版。
