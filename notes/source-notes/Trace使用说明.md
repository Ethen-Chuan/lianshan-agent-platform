# Trace 与 Bad case 演示说明

本版增加项目助手任务关联。在「项目助手」的每个步骤可查看 Trace 或登记 Bad case；Trace 详情可返回对应任务。“查看任务 Trace”按任务编号筛选，失败重试后的旧记录不会被覆盖。登记问题后，继续使用下面的归因、回流与离线评测流程。详见 `SuperAgent使用说明.md`。

## 推荐先看这条执行

进入“自动化助手 → 执行追踪”，打开“B2 蓝牙断连：知识版本不匹配”。

左侧依次列出接待、检索、候选回复、质检和人工转接。点击检索步骤，可看到请求版本 V4.0.2，返回知识版本 V3.9.0。后续质检拦截正常；待排查点是上游检索为什么没有先过滤旧版本。

每条记录提供来源、Trace 编号、Span 编号、上级步骤、助手和工具、输入输出、耗时与版本。这里展示的是可核验的调用数据与简短处理摘要，不展示隐式思维链。预置样本不是从客户系统采集的日志。

## 从问题登记走到回归发布

1. 点击“查看问题 BC-0001”，填写人工归因、预期行为和修正方案，例如在检索时核对软件版本。
2. 保存分析，点击“加入回归样本”。确认预期、权限与脱敏后，才保存样本。
3. 进入“评测与发布”，先不修改候选，运行回归检查。该版本检查会失败，保留旧版知识被使用的输出。
4. 勾选“检索时核对软件版本”，保存候选规则，再运行检查。基线和候选逐项对比，候选输出应为不使用旧版本并转人工。
5. 检查通过后仍需人工审核。可选择“不通过，继续修正”，填写原因；也可确认通过并发布到演示评测环境。
6. 发布后案例标记为已关闭，保留样本、评测、版本和审核依据。到执行追踪新增模拟执行，选择“回放当前评测版本”，可查看新策略的本地结果。
7. 在发布记录中回退，旧策略恢复，关联问题重新进入待回归。

更改修正方案、候选规则或样本都会使旧的发布依据失效。检查通过率只描述列出的规则分支，不等于模型准确率，也不是自动训练效果。

## 新增多助手执行

在执行追踪点击“新增模拟执行”，选择“多助手接待：报修草稿待确认”。

本地接待函数读取知识列表并返回预设回复；填单函数整理已知字段；检查函数核对缺项和回复风险。六个步骤的输入输出均来自本次本地函数结果，耗时为本地测量。受理部门缺失时停在人工确认，不创建工单。

已有工作台中的助手测试、发送前拦截、确认建单、人工请求以及取消延迟回复也会记录 Trace。同一会话的多次执行会相互关联，原来没有埋点的历史过程不会被补造成真实调用链。

## 知识与样本的边界

问题案例可以转成待审核知识草稿。草稿只包含问题来源和修正提案，不会自动作为客服答案。已有草稿可从问题详情打开，由知识模块另行审核。

回归样本保留原始观察、人工预期、来源版本和修订号。旧评测保留当时的样本快照；更新样本不会重写历史结果。

四类规则有可执行演示检查：版本不匹配、工单缺少版本、工具超时、未审批承诺。表达或其他开放式问题没有通用判分器，显示待人工验证，不自动通过发布。

## 数据导出与安全

导出先确认用途，范围为当前筛选的 Trace 及关联案例、样本和评测片段。片段导出明确不是完整发布包。JSON 下载到本机，没有上传接口。

演示会移除疑似凭证、联系方式等敏感字段，但前端规则不是生产级脱敏系统。不要输入真实客户信息，对外分享导出文件前需要再次扫描并人工检查。

## 数据记录

| 对象 | 主要字段 | 用途 |
|---|---|---|
| Trace | id、caseId、parentTraceId、origin、versions、spans | 关联一次执行和同一问题的其他执行 |
| Span | id、parentId、agent、tool、input、output、duration、summary | 定位具体步骤；summary 为可展示的处理依据 |
| Bad case | traceId、spanId、cause、expected、fix、owner、revision、history | 人工分析与问题跟踪 |
| Sample | badId、input、observed、expected、sourceVersions、revision | 保存经确认的回归输入与标准 |
| Run | baseline、candidate、results、guard、fingerprint | 保存不可被当前编辑覆盖的评测快照 |
| Release | runId、version、previous、note、status | 审核发布与回退追踪 |

所有数据仅保存在浏览器本地，不提供租户权限、持久审计、真实模型评测、生产发布或训练能力。
