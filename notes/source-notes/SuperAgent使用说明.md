# 项目助手 · 对话版体验说明

## 打开就能聊

默认首页就是项目助手。输入框无需打开弹窗或进入任务卡。选择推荐示例只会填入文字，按 Enter 或发送按钮后才会执行。

> 处理 CS-0108 和 CS-0107，核对方案，准备回复和报修草稿，先不要发送。

项目助手分别处理两个客户；知识查找和工单整理可以并行，后续回复与检查等待前置步骤完成。进度和结果直接出现在对话中。

默认最多并行 6 个任务，每位助手同时执行 2 个步骤。在“助手状态”可配置 1–12 个并行任务、每位助手 1–4 个并行步骤，刷新后保留设置。这是本地演示的资源策略，不是 Orbit 能力上限。同一会话的不同任务串行，步骤依赖仍须满足；降低上限不打断已开始的步骤，后续调度遵守新上限。对外发送与建单仍须人工确认。B2 演示会话缺少匹配的已发布方案，会收到模拟专家协作返回，但不会冒充真实专家结论。

## 继续补充

- `任务状态`：查看当前任务；也可明确写 `查看任务 PM-0002`。
- `暂停 PM-0002`、`继续 PM-0002`、`取消 PM-0002`。
- `只重查方案，保留工单草稿`：仅重查当前选中任务的知识及后续依赖，保留工单草稿。
- `安排专家协助`：在当前任务中安排模拟协助，不外发资料。
- `查询 CS-0106 的工单进度`。
- `只复核 CS-0104 的已有对话`。

省略任务编号时操作当前选中任务；批量任务最好写明 PM 编号。新对话没有任务时不会自动操作上一段对话。

这是有界的本地规则解析，不是通用模型。无法识别的指令会提示改写，超出权限的退款、删除、发布和自动发送会被拒绝。

## 新对话与历史

左侧“发起新对话”开启独立对话。历史入口在左侧和顶部“对话记录”中，窄屏也能访问。

切换对话保留当前页面内的未发草稿。页面刷新后草稿不保留，已提交消息与任务保存在本地。运行结果回到原来的对话，不插入你正在处理的另一段对话。

## 分工、Trace 与问题回流

“分工与执行记录”在右侧展示当前任务的上下文、步骤、调用次数、输入输出、错误和协作记录。工具输出默认折叠，展开状态不会被步骤更新打断。

每个完成或失败步骤都有 Trace。可登记 Bad case，填写业务归因、预期输出和修改建议，再经过脱敏确认、样本回流、回归检查与人工审核。

顶部“助手”显示各助手的当前任务与等待情况；“任务记录”可按状态或参与助手筛选。任务记录底部提供一次查询超时演示，失败后可重试并保留原记录。

PM-0001 是未运行的预置计划，只在任务记录里保留。输入新指令不依赖它。

## 结果确认

回复、工单信息与检查结果会直接显示。人工审核区按任务展开，填写说明后才可确认或退回。

确认只是完成准备任务：不发送、不建单、不改变客户问题的解决状态。发送要回到坐席；建单要完成表单。已有坐席草稿不会被直接覆盖。

资料改变后禁止使用旧结果。可在执行详情中刷新资料重跑，历史轮次和失败 Trace 均保留。

## 模拟 CLI

输入区“对话”按钮可切换到模拟 CLI。两种输入使用同一批任务。

```text
help
run CS-0108,CS-0107 service
run CS-0106 lookup
status PM-0002
pause PM-0002
resume PM-0002
retry PM-0002
cancel PM-0002
assist PM-0002 expert
rerun PM-0002 knowledge
```

CLI 不执行系统程序。最多重试 3 次实际调用，每个任务最多 4 次附加协作。

刷新会暂停未完成任务，检查后才能继续。没有真实后台任务服务器、模型、企业渠道或外部 Agent 连接。
