# 客服回复写法

这份规则用于编写本版示例回复。未来接入真实模型时，还需要结合知识检索、工单状态、权限和人工复核一起使用，不能只靠文风提示保证事实正确。

## 对客户说什么

直接回应当前问题。步骤足够时就给步骤，需要查证时说明查什么，不用“已识别到服务诉求”“为您提供全方位帮助”等开场。

客户已提供的型号、版本和尝试过的操作，不要重复问。不能因为一条消息没包含这些信息，就忽略前面的对话。必要时只确认有歧义的部分。

处理状态以工具结果为准。没有建单回执就不能说“已创建”，分派待办不能说“专家已接单”。未来模型使用本规则时，不得把本 Demo 的模拟状态当作真实执行结果。

涉及换机、收费、退款或时限，保留核实条件。语气可以简单，不把“不能确定”改成“没问题”。风险警示不应因去套话而被删掉。

保留 AI 身份。不要编造真人经历、打字错误或情绪来模拟真人。

## 示例

| 场景 | 回复示例 |
|---|---|
| A1 软件版本查询 | 在设备设置里打开“系统信息”，就能看到“软件版本”。如果菜单名称不同，告诉我您看到的选项。 |
| 已提供信息，请求报修 | 可以，现有信息可以先填进报修草稿，核对后再提交。 |
| 专家待办已分派，尚未接单 | 已给专家分派待办，还在等待接单，暂时没有新的处理结论。 |
| 换机资格未核实 | 能否更换、是否收费，需要专员核实检测结果和服务政策，目前还不能确定。 |
| 没有适用方案 | 暂时没有适用的处理方案，需要技术同事进一步确认。 |

## 工作台文案

标题写功能，按钮写动作，提醒写原因和下一步。保存成功时说“已保存”；需要补项时指出具体字段。重复的产品说明收进帮助区；输入真实信息的警示、风险拦截和建单确认仍留在操作位置。

## 复核

比较改写前后是否改变了事实、条件、完成状态或责任主体。自然程度依靠人工阅读判断，不使用自评分或检测器分数当验收结论。
