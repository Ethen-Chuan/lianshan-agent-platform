# Agent 协作工作台改进与验收

日期：2026-11-10。范围：本地脱敏版原型。没有提交、推送或部署，也没有改变用户正在使用的浏览器数据。

## 产品取舍

团队主要由 Agent 组成，不再要求用户先区分“项目助手单聊”与“项目群”。项目助手保留为协调角色，工作入口合并为 Agent 协作工作台。业务事实共享与执行权限分离：项目定义共同使用，客户信息属于具体任务，退款、删除、对外发送或正式业务写入不会因进入群聊而获得授权。

## 评审意见与落实情况

| 评审意见 | 本轮实现 | 边界 |
| --- | --- | --- |
| 收敛入口与任务 | 一个协作工作台，含协作、任务与待确认、共享业务信息、效果与验收；旧 manager 链接兼容进入 group | 不删除、不复制旧任务；历史独立对话只读，不自动转发 |
| 把任务做完而非只展示消息 | 群任务直接进入回复草稿、工单草稿和审核；失败步骤可重试；查看当前任务快照 | 人工确认只结束准备任务，不把客户会话自动标为解决 |
| 明确能力成熟度 | 画布节点、研发与发布页显示本地规则、未接工具、非生产执行；提供上线检查 | 不提供可手动勾选的“生产可用”状态 |
| 客户服务闭环 | 客户自助预览覆盖知识解答、缺项追问、风险交接、查询超时；带上下文进入客服收件箱 | 只支持有限本地规则与示例产品，不连接真实客户渠道 |
| 信息共享与权限分离 | 共享定义按项目、客户快照按任务；明确字段来源和未验证信息；授权不足时拒绝本地分派 | 服务端身份、字段级权限、租户隔离与凭证管理仍是生产阻断项 |
| 让本体价值可体验 | 共享库可直接复用为新助手；引用变化展示原值、新值及当前研发场景的关联验收集 | 不自动覆盖旧配置；关联案例待复核不意味着已经失败 |
| 强化评测与反馈 | 正常、缺项、转人工三类均须人工审核预期并全部通过；沿用 Trace → 问题案例 → 回归样本 → 新版本 | 本地规则通过率不代表模型准确率；真实工具接入后须追加超时、权限、写入等验收 |
| 减少视觉层级 | 保留米白、苔绿；固定各协作视图内容宽度；身份与全局排版按需展开；画布旁提供 Agent 调整入口 | Agent 调整仍为本地确定性指令，不执行任意语义 Prompt |
| 图谱辅助思考 | 默认业务分区；关系探索围绕当前元素，点击邻居切换中心，窄屏分层；保留关系清单 | 排列不是因果关系，流光不是后台执行 |
| 效果口径可信 | 分开统计准备任务、有效边界验收、客户确认的本地自助演练 | 没有真实自助解决率、模型成本、经营成绩或生产性能数据 |

## 可直接体验的路径

1. 打开 `?project=AFTERSALES#group`，发起报修准备，等待结果后进入「任务与待确认」。先核对依据，再将草稿带入坐席或工单核对窗口。
2. 初次协作页可选择「演练查询失败与重试」。失败显示在原任务上，重试保留任务身份与历史事件。
3. 「体验客户自助」选择设备报修，补充示例软件版本，带上下文转人工。进入客服后展开交接摘要；再点「Agent 协作」会带入当前客户会话。
4. Orbit → 共享业务定义 → 复用为新助手。创建两份引用同一规则的草案后，修改该规则，在「变更影响」查看两份配置与关联验收集；原快照保持不变。
5. 进入「效果与验收」核对本地统计口径，再看「能力与上线检查」中的真实接入缺口。

## 实现与兼容

- 新增 `app/agent-workspace.js`、`app/service-journey.js`、`app/agent-workspace.css`，复用原任务引擎与研发数据，不另造一套任务状态库。
- 售后项目继续引用原 ManagerHub 任务；其他项目只读取自身 ProjectStudio 任务。两种来源使用不同引用键，避免编号冲突。
- 自助会话保留在 `serviceJourney` 中，仅售后演练入口可见。转人工按会话幂等创建一个本地客服记录，不自动创建工单。
- 客户后续继续提问会撤销先前的本地解决标记；型号不匹配、版本冲突、知识停用、升级问题或超出本地范围会转人工，不套用查看版本的答案。
- 本地自助查询超时的重试不会伪造成功回执。客户渠道停用时保留记录并阻止交接。
- 未新增远程字体、运行依赖或第三方数据请求。公开静态构建继续使用原有资源白名单。

- 检查键盘与减少动态效果偏好；保留表单焦点、画布键盘移动、点击连线替代、关系清单和可暂停动效。
- 截图只保存在本地工作目录，不加入公开站点或 README 图库。原 README 图片明确标为首次发布截图，不冒充最新界面。
