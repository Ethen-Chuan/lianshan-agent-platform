## 定位与本轮范围

连山恢复为业务助手平台：Super Agent 接收目标与统筹业务助手；客服工作台是首个业务场景，继续放在导航最上面。群聊就是统一协作入口，旧 Manager 链接进入同一页面，不新增 Harness 菜单。

Ontology 提供业务定义，Orbit 用于配置、验收和发布本地助手版本。新模块 `app/agent-harness.js` 是纯本地运行约束层，不是已经接入真实模型的自治 Agent 引擎。本轮没有执行任意自然语言业务逻辑、遍历任意画布分支或调用外部业务系统。

## 已打通的链路

1. **编译执行规则**：合并配置、本体引用快照和流程定义中的必要字段；本体结构化转人工词、禁止词不能通过清空配置框绕过。只接受本地摘要与表单草稿两个动作。
2. **统一验收与运行**：案例验收和正式本地任务使用相同编译器与执行检查。正常、缺项、转人工三类案例都须由用户确认预期并通过，发布时冻结规则、配置及运行器版本。
3. **按项目分派**：受理关键词唯一匹配时可分派定制助手，包含售后项目；多位助手匹配时要求明确指定，不随机选择。原有 `@项目助手`、`@项目经理` 与新的 `@SuperAgent` / `@Super Agent` 均可用。
4. **预览不执行**：预览分工不会创建任务、生成回执或调用动作。提交时重新检查，预览不是一次可以绕过后续授权的许可。
5. **缺项与冲突拦截**：必要字段须按“字段：内容”填写；空值、未知值和同名字段冲突不能进入动作准备。提及助手名字不作为命中业务范围的证据。
6. **限定工具上下文**：本地动作只接收所需字段，不把整段输入、内部备注或其他任务资料拼入草稿。用户填写的内容仍标为待人工核实，不宣称已查询到事实。
7. **结果与来源检查**：记录动作类型、规则版本、每轮检查、本地回执和草稿。回执明确 `local-draft`、`externalWrite: false`，不是外部系统确认。
8. **继续同一个任务**：缺项任务可补齐完整描述后重跑，保留原编号和历次输出；每个任务最多三轮。风险转人工不允许通过这个补字段入口直接恢复自动处理。
9. **人工核对**：核对说明和明确勾选缺一不可。再次检查助手授权、版本和草稿与输入的一致性；确认不会发消息、写入真实工单或把客户标为已解决。
10. **防重与存储失败处理**：相同助手、版本和当前输入的重复提交被拒绝；任务、轨迹、补充轮次、结果确认和版本发布在保存失败时回滚。历史独立对话不自动转发。

## 文字规则不是已执行的程序

可自动执行的范围是结构化关键词、必要字段、项目范围、成员授权、动作白名单、结果字段、轮次与版本检查。

本体中的自然语言规则，以及画布中的任意业务条件和分支，不会被自动翻译成程序。它们会作为人工核对清单展示。保修资格、设备编号真实性、政策适用性等仍需要真实证据，不能由“字段有值”代替验证。

画布产生的 `flowDesign.execution` 仍是 `definition-only`。本轮只消费其中的字段定义和人工检查说明，不把整张图标成执行成功。未来接入真正流程执行器时必须定义分支表达式、动作适配器及独立验收。

## 版本与历史兼容

- 旧助手、头像、场景、案例、版本和消息全部保留，不自动迁移或批准。
- 旧的 `local-scene-1` 验收不能作为新运行器的验收证据。旧助手版本执行时提示重新验收；重新发布得到下一版本，旧版本不覆盖。
- 修改当前本体或研发草稿，不回写已发布快照。
- 任务补充和结果确认要求助手当前版本仍与任务版本一致；如果已切换版本，保留旧任务，要求按新版本重新发起。
- 配置与冻结规则不一致时拒绝运行。此处是本地一致性检查，不是数字签名或防篡改服务。
- 预设售后 ManagerEngine 保留原有本地步骤、失败重试、结果交接；分工预览复用真实计划。它尚未绑定 Orbit 发布版本，不能宣称已经全部迁入新运行器。
- 调度信息读取实际并发设置，不再显示旧的固定“2 个任务”说明。

## 本地体验

1. 打开售后项目的 **Super Agent**。客服工作台继续是第一项；也可从当前会话点击“交给 Super Agent”。
2. 在协作侧栏点击 **体验规则检查示例**。系统从当前本体创建一份草案和三条未批准案例，不会自动发布或自动确认。
3. 核对案例和预期，运行本地验收；在“纳入团队”填写原因并确认。配置与发布页可看到真正参与执行的字段、动作边界和人工规则。
4. 在助手目录点击“在团队中使用”，参照正常案例输入目标。先“预览分工”，再发起任务。
5. 故意省略一个必要字段：任务应显示待补充，执行记录显示没有调用动作、没有回执。在任务详情补齐后，原任务产生第二轮记录和本地草稿。
6. 核对来源及文字规则，填写说明并勾选确认。本地任务可完成，但不会自动对客发送或创建业务单据。

## 开发与回归门禁

- `npm run test:harness`：运行 Harness、统一工作区与客服闭环的针对性测试。
- `npm run check`：先按白名单构建，再运行全部自动化测试；任一步失败返回失败，不发布。
- 新增或变更规则时，先补正常、缺项、冲突、风险、越权和版本变化案例，再修改运行代码。
- 编译或运行语义发生不兼容变化时，更新 `AgentHarness.version`，让旧验收失效并要求重新验收；不得默默套用新规则到旧任务。
- 新外部动作不得只加入前端白名单。必须先具备服务端授权、真实适配器、幂等与回执恢复方案、超时和错误结果验证。
- `npm run build` 只生成本地 `site/` 与 `docs/`，两者一致，不代表线上发布。
