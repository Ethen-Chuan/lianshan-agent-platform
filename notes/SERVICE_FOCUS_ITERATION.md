# 先让一次客户服务完成：功能取舍与待打通清单

日期：2026-11-10。依据本地源码与自动化测试；不是生产调研结果，也不是线上发布记录。

> 后续决策：用户明确保留 Super Agent 平台定位。“群聊退出默认导航、只展示两个助手”的取舍已被撤回；客服闭环与知识编辑改进仍保留。现行入口、运行规则与待接入边界见 [Harness 本地迭代](HARNESS_ITERATION.md)。下文是当时的分析记录，不作为当前导航设计要求。

## 1. 用什么判断功能是否必要

服务对象是提出售后问题的客户；客服与服务运营是使用平台处理问题的人，Agent 是处理方式，不是产品目标。

当前只保留能直接回答以下问题的默认功能：

1. 客户的问题和已有信息是否被正确接收？
2. 有依据时能否回答，没依据时能否交给人？
3. 需要查询或处理时，是否得到可核实的业务结果？
4. 客户是否收到结果，并有证据说明问题解决或尚未解决？

助手数量、群聊消息数、图谱节点数、动画复杂度都不能回答这些问题。不把它们当作当前产品的完成标准。

## 2. 本轮取舍

| 功能 | 判断与处理 | 重新扩大投入的前提 |
| --- | --- | --- |
| 客服工作台 | 保留为售后项目默认入口，包含会话、接管、回复、资料与填单 | 核心流程，不需再证明存在价值 |
| 工单记录 | 独立一级入口，不再隶属于助手标签页 | 后续接入一套真实或沙箱工单系统 |
| 知识库 | 保留审核与适用范围；版本查询直接使用已审核正文 | 不把编辑知识等同于训练模型 |
| 接待、填单助手 | 默认只展示这两项服务能力；配置与验收按需进入 | 新职责确实需要独立规则、权限或验收时再增加助手 |
| 风险拦截与人工确认 | 保留，不作为需要另行建立团队的步骤 | 不为减少点击而删除发送保护或提交确认 |
| Orbit 与业务本体 | 保留在业务助手内部，作为新规则设计入口 | 至少有一个被复用的字段/规则和可验证的执行适配器 |
| 群聊与多助手调度 | 退出默认导航和工作台快捷入口，保留实验记录 | 单助手无法完成的跨角色协作，有真实工具与明确交付物 |
| 固定样本大盘、问数助手 | 退出默认目录与全局搜索，收在项目设置中 | 统计能追溯到同一服务事件链，并有需要根据指标作出的运营决策 |
| 业务实例图谱 | 退出主流程，避免和业务本体混用 | 有真实对象标识、关联事件和文本列表不能解决的查证任务 |
| 独立会话评分 | 暂缓作为默认能力，风险复核继续保留 | 评分标准经过人工校准，且结果有明确改进责任人 |
| 重复接待测试、独立填单演练 | 从默认入口移除；接待在客户预览测试，填单从具体会话进入 | 旧页面仅用于查看历史，不建立第二份业务事实 |
| 自定义助手、其他项目 | 保留配置和版本；定制助手在默认目录按需展开 | 未接入客服执行前，不宣称已能服务真实客户 |

“退出主流程”不等于删除历史数据。本轮没有删除助手配置、客户记录、任务、项目、知识、验收案例或已发布快照；也没有通过改变权限开关制造接入成功。

## 3. 已确认的断点与本轮修复

| 环节 | 原状 | 本轮结果 / 剩余边界 |
| --- | --- | --- |
| 本地服务加载 | 本地服务器维护旧的手写白名单，遗漏 Orbit、客户自助等新模块 | 本地与构建共享 HTML 资源清单；所有页面依赖通过请求处理器检查。后端、私有路径、未知 Host 仍拒绝访问 |
| 客户自助 → 人工 | 只复制一次消息，转人工后客户端不能继续发送，也看不到后续回复 | 交接后使用关联会话作为消息来源，不再复制另一套后续记录；补充、回复、回告可往返 |
| 客户可见范围 | 尚无客服回复回流能力 | 仅显示 customer、agent、staff 消息；内部备注、系统审批和其他会话不进入客户投影，关联会话标识不匹配时拒绝使用 |
| 工单回告 | 仅在客服对话中追加本地消息 | 同一消息可在客户预览看到；相同状态重复回告不会重复追加。本轮仍没有外部系统回执 |
| 结果确认 | 客户自助确认与人工处理记录断开 | 显式客户确认同时写入本地会话证据；创建/完成工单和客服自行记录结果不自动视为客户确认。后续反馈使原会话重新处理 |
| 知识编辑 → 解答 | 判断知识是否发布，但版本查询回复正文硬编码 | 版本查询读取已发布、产品匹配且通过现有风险检查的知识正文；历史消息不回写。不是通用语义检索 |
| 接待配置 | 客户演练没有检查接待助手启停/模式 | 暂停或非自动接待模式转人工，不继续自动回答 |
| 回复权限 | 未知渠道或只接收不回复的配置存在发送判断缺口 | 客服回复要求已知渠道、读写许可、非停用和可回复来源；保留人工接管条件 |

核心代码：`app/app.js`、`app/service-journey.js`、`app/project-hub.js`、`app/server.js`、`scripts/public-assets.js`。样本数据、字段提取、风险规则均仍是本地实现。

## 4. 仍未打通的环节，按依赖顺序处理

### 第一项：服务端保存同一条会话

- 统一项目、客户、会话、消息、工单、执行与结果的关联标识。
- 建立服务端存储、身份校验、数据隔离和事件记录；客户端不再凭本地状态授予权限。
- 验收：两个经过授权的测试客户端读取同一会话；刷新与服务重启后记录仍在；重复消息只处理一次；越权项目读取失败。
- 这一步先解决持久化与一致性，不需要增加新的导航或复杂 Agent。

### 第二项：真实模型执行一项受控业务

- 现有模型接口只发送固定连接测试文本，不接收业务问题，也没有知识检索/工具执行。
- 增加受控服务端业务接口，先选低风险的“在哪里查看版本”，带审核知识与适用范围。
- 验收：正常问题有可核对引用；未发布/不适用知识不可引用；没有依据、超时、客户要求人工时可交接；不编造版本、承诺或执行结果。
- 连接测试成功不自动授权业务调用，密钥仍不得进入静态站点和浏览器存储。

### 第三项：接一套工单系统，而不是先做连接器市场

- 先查询已有工单，再做人工确认后的创建；限定一个沙箱或试点系统。
- 定义必填字段、错误响应、受理权限、幂等标识与回执查询。
- 验收：同一提交重复点击/重试只有一张单；超时后先核对是否已创建，不能直接再建；真实回执编号、状态和来源进入同一会话记录。

### 第四项：接一个真实客户入口

- 在前三项有受控后端后接一个官方测试渠道，不同时做多个平台。
- 验收：消息验签、身份映射、去重、发送回执、失败重试、人工接管后的停止自动发送，以及恢复后的顺序一致。
- 客户端消息不得夹带内部备注、审批依据或其他客户上下文。

### 第五项：把真实结果写回并可核对

- 区分已回答、已转接、已建单、已回告、客户确认、人工核实、未解决关闭。
- 验收：每一个解决结果可追溯到证据；没有回复、任务准备完成、工单创建成功都不自动计作解决；重复咨询有明确重开或新建规则。
- 在这之前不把固定样本大盘改名为“实时效果”，也不填造提升比例。

### 第六项：再开放自定义流程与多助手

- 当前画布保存布局与定义，Prompt 保存草案；关键词与字段检查不是通用工作流执行引擎。
- 先明确节点类型、输入输出、条件、权限、取消/超时/重试规则，再绑定已验证的模型和工具适配器。
- 验收：图上的每一步对应真实执行记录；越权、缺项、失败不会继续写入；变更必须经过样本回归并支持回退。
- 只有出现可验证的跨角色需要，才把群聊协作重新提升为常用入口。

## 5. 推荐下一次只做什么

**只做“一条脱敏报修会话的服务端保存与双端回读”。** 不同时增加图谱、模型市场、助手角色和运营大盘。

之后接模型与外部系统时，需要确定一个模型连接、一个有授权的工单沙箱、一个测试客户入口，以及一组已审核的正常/缺项/风险/失败样例。凭证只通过受控配置提供，不粘贴到公开仓库、聊天示例或页面脚本。

## 6. 验证与发布边界

- 已运行构建、单元测试、页面模板/业务事件测试、静态请求处理器测试与公开产物一致性检查。
- 请求处理器测试直接使用服务器入口，不冒充真实 HTTP 连通测试。
- 当前执行环境无法连接浏览器控制桥；本机预览进程在运行，但沙箱不能访问其端口。本轮不宣称已完成浏览器视觉验收、真实网络联调或生产验收。
- 已更新受导航变化影响的浏览器测试脚本，但尚未在浏览器执行。后续需要验证桌面/窄屏布局、端到端建单与回告、刷新恢复，以及历史链接兼容。
- 修改前备份位于工程外的本地工作目录。公开构建只包含允许的静态资源；本轮未提交、推送或部署。
- 自动脱敏规则未发现明确凭证；示例指标、比例等仍触发中风险提示，不可当作真实经营成绩。
