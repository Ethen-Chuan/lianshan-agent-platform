# Orbit：从本体图谱到业务助手研发工作台

日期：2026-11-09。此轮仅修改本地脱敏版，未提交、推送或发布。已有图谱可读性改进与原有项目数据继续保留。

## 产品变化

Orbit 的默认入口改为「业务设计」，不要求业务人员先建立本体图。完整路径为：描述业务 → 整理待确认草案 → 确认配置 → 案例验收 → 人工纳入本地团队。

### 1. 复用共享定义

- 共享库显示当前项目的对象、规则、表达、动作定义和必要信息。
- 支持新增定义，并可明确建立「已有定义 → 新定义」的关联；不会自动获得业务工具权限。
- 每项定义显示配置草案与当前助手版本的引用。历史版本不重复计数。
- 本体图保留为查看、编辑定义及有向关系的辅助界面，不作为创建新业务的必经步骤。
- 本体动作生成的配置保留独立快照；候选原因不作为事实依据带入。

### 2. 区分业务需求、真实能力和依据

- 创建助手时保留完整业务描述，按原文句段整理待确认要求；可以不选择任何已有本体动作。
- 能力需求可自由登记，不再把两种本地演练方式当成整个产品的能力范围。
- 显式展示两种可用的本地演练方式、待接入工具需求、模型未连接和字段来源未核实。
- 本地整理是确定性的文本与配置整理，不调用语义模型，不声称理解并验证了任意业务逻辑。
- 用户确认后的初始业务描述及需求保存在 `config.businessDesign`；后续保存配置不会丢失这些来源信息。
- 编辑业务描述会撤销尚未确认的预览；选中的定义更新后需重新整理，避免确认过期草案。

### 3. 规则变更影响

- 对比引用快照和当前动作的实际依赖，而非只比较版本号。
- 展示字段、定义、条件、依赖节点和关系的新增、移除与改动，包含原值和当前值。
- 无关原因假设或图谱位置变化不会把配置标为受影响。
- 配置草案和当前助手版本分别检查；已有发布记录不被改写。
- 「用当前定义另建草案」仅建立新的本体配置，不声称自动迁移原草案个性化 Prompt、案例或其他修改；界面明确提示人工迁移。

## 视觉与动效

保留既有中文字体和连山米白、苔绿调性。强化标题层级、列表阅读、留白与对比；使用深绿轨道装饰作为视觉重点，而非把运行状态伪装成发光连线。

页面和草案使用短距离淡入；按钮使用轻量反馈。轨道为慢速装饰动效，可独立暂停。系统开启减少动态效果时禁用新增动效。手机保留创建、定义维护、能力登记和变更检查功能。

## 实现与边界

- 新增 `app/orbit-workbench.js`、`app/orbit-workbench.css`；接入现有 ProjectStudio、OrbitOntology 与项目隔离存储。
- 保留原有本地规则执行、案例人工确认、版本快照和项目群协作。
- 未新增第三方依赖、远程字体、真实模型调用、外部接口、凭证输入或权限开关。
- 不承诺查询到真实保修状态、创建真实工单、获得业务权限或自动发布到生产环境。
- 普通草案未填写受理关键词和必要字段时，仍需人工配置；不能用空白配置通过验收。

## 后续优先级

优先接通一个真实语义模型与只读业务工具，建立可验证的来源证据；之后才加入经授权的写操作。当前 UI 不应先于实现显示「已接入」或「已执行」。
