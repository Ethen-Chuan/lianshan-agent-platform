# 连小山：后台模型协作试运行

日期：2026-11-11。状态：本机实现，未推送或部署。

## 本次解决什么

过去的群聊用本地规则安排预设步骤。此次新增一个受限的模型协作运行器：连小山接收目标、调用模型规划分工，业务助手各自调用模型准备草稿。同一任务可以继续补充，其他任务无需等它结束。没有把预设消息改名成模型结果。

工单记录仍归「业务助手 → 工单填写助手」，不新增侧栏。记录页先选择可用客户会话，已有工单直接打开，缺项继续原草稿；不会默认对上次选中的客户建单。

## 入口和使用

在项目根目录运行 `PORT=4342 npm start`，打开 `http://127.0.0.1:4342/?project=AFTERSALES#group`。

- 首先在「团队与模型」连接连小山及至少一位启用、已授权业务助手。每位助手独立配置；密钥只在服务进程内存中，不进入任务数据库。
- 输入本轮目标，按需选会话、知识和已验收业务定义。发送前可以展开核对资料，默认不带客户上下文。
- 每轮单独同意资料外发和模型费用。最多一次协调请求、三次业务助手请求；每项任务最多 6 轮、包含恢复在内最多 12 次处理尝试。单次模型请求最长等待 45 秒，不自动重试。
- 连小山安排分工，接待助手准备答复、填单助手整理资料、复核助手检查前置草稿。只分派给本轮已连接且允许使用的助手。
- 「需要我」显示待补充、待核对、失败和中断。继续补充保留原任务，携带上一轮问题及结果，停止后的任务不能靠新消息悄悄恢复。
- 「核对并确认草稿」只记录审核，不给客户发消息、不提交工单，也不记成问题已解决。
- 「进入填单助手」目前是进入原有业务工作区，不会自动将模型文字映射到单据字段。单据仍从授权客户会话按原规则准备，人工确认后才创建本地模拟工单。

## 设计借鉴及取舍

参考用户提供的 Super-agent 架构长图，以及公开仓库 [deepseek-ai/dsh-superagent-prototype](https://github.com/deepseek-ai/dsh-superagent-prototype)。重点阅读其 philosophy、domain、authorization、execution、panel 和 architecture 文档。

仓库明确说明它是研究原型，不是 DeepSeek 正式产品，也不是生产就绪软件；文章中的部分构想尚未在其原型实现。本项目借鉴职责拆分与交互方式，没有复制其实现，也没有复刻整套编码代理。

| 参考思路 | 连山中的落实 |
| --- | --- |
| 协调者与执行者分离 | 单独的连小山模型连接只规划；业务助手按步骤生成结构化结果 |
| 快速接收，后台推进 | 接口接收后立即返回任务编号，后台排队，聊天不等待工作结束 |
| 每件事有自己的执行上下文 | 不同任务使用各自资料快照；同一任务保留补充与历史轮次 |
| 人的注意力集中在结果与异常 | 默认少显示运行细节，待补充、待审核与失败可筛选 |
| 可恢复而非假装持续运行 | SQLite 保存进度，重启标中断，需要重新确认后才能调用模型 |
| 明确授权来源 | 本机访问校验、逐轮费用确认、白名单助手、无外部写入工具 |

没有采用参考编码代理的任意 shell 执行方式。客服场景中共享信息不等于操作授权，因此本轮不提供任意 HTTP、文件、CRM、退款或发送工具。

## 实际接通的环节

接收消息 → 校验本轮授权与资料 → 持久化 → 协调模型规划 → 业务模型顺序处理 → 核对结构与引用 → 等待补充或人工核对。

- 跨任务并发可设 1–6，默认 3；同一任务内按依赖顺序执行。调高并发不是生产吞吐承诺，也不保证服务商额度。
- 每条输入有幂等标识。网络结果未知时，重试同一请求不再创建任务；明确拒绝后可修改草稿。
- 停止与补充会中止旧处理，迟到的结果不会覆盖新轮次；模型连接版本变化也会拒绝旧结果。
- 保存失败暂停全部任务并显示原因，避免继续执行却丢记录。重启不自动补发付费请求。
- 草稿按任务保留在页面内存中，刷新页面会清除未发送草稿；已接收任务由本机数据库保存。
- 客服工作台进入模型协作可预选原会话，但不会自动发送。点击旧任务则返回规则模式，避免旧任务链接被新界面遮挡。

## Orbit / Ontology 的边界

可选择已经验收的 Orbit 版本，将其必要字段、人工检查规则和版本带入本轮资料。这些是模型参考，不是任意流程的执行授权，也不构成模型执行已通过该业务验收。

本轮模型角色固定为协调、接待、填单、复核。Orbit 生成的定制助手仍使用原规则运行器，尚未自动成为后台模型 Worker；对应头像、版本、旧任务及验收记录不改写。「规则演练与旧记录」仍能打开它们。两个运行模式的任务不自动合并。

## 数据与运行限制

- 仅售后项目和本机单一可信操作员。Host、Origin、跨站检查及随机会话标识保护本机接口，**不等于**企业用户身份、角色权限与多租户隔离。
- 发送最多 8 条客户原话、6 篇已发布知识，以及可选定义；不读取内部备注或其他任务。总资料长度受限。
- 客户说法和助手草稿不等于已核实事实。引用检查只确认 ID 属于本轮资料，不证明事实正确。
- 已接收任务使用固定快照。浏览器里的知识停用、助手暂停或授权调整不会自动撤回已接受任务；应停止任务后重新发起。移除服务端模型连接会中止该连接的运行请求。
- 本机数据库在 `work/super-agent/tasks.sqlite`，目录权限 0700、文件权限 0600，已从版本管理和静态站点排除。不是加密数据库；任务资料仍需使用脱敏样例。
- 最多保留 100 项任务，4000 条事件后不再开始新处理；停止与核对仍可用。暂无清理/归档界面，保留原数据库，不建议通过删除记录绕过限制。
- 浏览器关闭不影响尚在运行的服务。电脑睡眠、关机或服务退出不能持续工作；服务恢复后需重新配置模型并明确恢复。
- 静态 4340 预览和 GitHub Pages 没有后台模型接口。不同端口拥有不同浏览器记录，不自动迁移旧数据。
